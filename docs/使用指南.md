# 使用指南

面向「不想敲命令、只想点按钮」的用法。全部在本机浏览器里操作。

## 打开

```bash
node workshop/server.mjs
```

然后浏览器打开 <http://127.0.0.1:4580>。窗口不要关，关了就停；只有这台电脑能访问。

## 四步写一本长篇

1. **出方案**：首页写一句想法（可以空着），点「帮我出 3 个开书方案」。
2. **选方案**：三个里挑一个，点「就写这本」——它会自动做设定集和前若干章章纲。
3. **写章**：进书页点「写下一章」或「连写 N 章」。
   - 每章可同时写多个版本，由评审模型挑出更好的那个，再打分。
   - 分数 **70+** 直接用；**55–69** 点「按评审建议改写」；**55 以下**点「删掉最后一章」重写。
4. **导出**：点「导出全书 TXT」，拿去投稿或用别的工具排版。

## 章节页能做什么

- 看评审报告：最好的地方、最伤追读的地方、改进建议、10 项得分。
- 看落选的候选版本，觉得落选更好就点「改用这个版本」。
- 「我自己改」直接在页面上改字。
- 每次改动前旧版本自动保存，页面下方可以回滚。

## 花钱

- 花费取决于你接的模型单价，界面右上方按 token 估算显示当天花销。
- 想控成本：把「候选稿 2~4」「评审」「评分」这些环节指给便宜模型，只让「主笔」用贵的。
- 任务中断了再点一次按钮，已完成的步骤不会重复花钱（产物落盘即复用）。

## 分数是怎么来的

- **评分（百分制）**：让一个模型扮演目标平台的签约编辑，按开篇抓力、冲突、爽点、脑洞、
  主角、节奏、对白、网文味、逻辑、章末钩子 10 项打分。
- **择优**：两个版本并排交给评审模型，前后换位置各判一次，两次一致才算赢；不一致时看文体相似度。
- **文体相似度**：跟你自己用 `workshop/build-baseline.mjs` 建的语料基线比段落长短、对白比例、
  句长、标点、套话、重复用语。**仓库里不带语料**，没建基线时这一项会被跳过。
- ⚠ 分数只用于排序和提示，不代表平台签约结果，最后还是自己要读一遍。

## 文件在哪

```text
projects/workshop-books/<书名>/
  bible.md              设定集
  outline.md            章纲
  chapters/0001.txt     定稿
  work/0001/            候选稿、场景节拍、评审明细
  history/              旧版本
projects/genres/        题材规则，改了下一章生效
```

## 出事先看两处

1. **终端窗口里的报错**——整段复制出来。
2. **书目录还在不在**——`projects/workshop-books/<书名>/`。

稿子不要删，留着才好查。

## 常见问题

**网页打不开**：端口被占了，换一个：`WORKSHOP_PORT=4581 node workshop/server.mjs`（Windows 用 `set`）。

**能连上模型但一直转圈**：多半是流式返回头卡住，检查接口是否为 `/v1/chat/completions` 形态；
这类问题在 `workshop/lib/llm.mjs` 里有超时看门狗。

**想换模型**：不用重启，改完配置下一次调用即生效。

**想加自己的题材**：在 `projects/genres/` 下加一个 md，写清读者预期、常用套路、禁忌。
